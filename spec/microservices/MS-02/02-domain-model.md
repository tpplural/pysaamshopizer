# identity-admin (MS-02) — Domain Model

**Service ID**: MS-02 · **Schema**: `identity_admin` · **Target DB**: PostgreSQL
**Traceability**: Segment 12 (User/Admin & Security), BR-USER-001..034 → BR-SC-* (this spec)

> Per ADR-004 the target delegates authentication to an OIDC provider — **credentials are not stored**.
> The legacy `ADMIN_PASSWORD` (unsalted SHA-1) and the security-question columns are NOT carried into the
> target schema; `idp_subject` links the admin record to the external identity provider. The legacy
> password/security-question rules (BR-SC-PWD-*, BR-SC-RESET-*, BR-SC-CREATE-005/006) remain documented in
> `01-business-rules.md` for traceability but are realized by the OIDC provider, not by columns here.
> No cross-service foreign keys: `merchant_id` and `language_code` are external references (xref) resolved
> by API/event, never by DB JOIN (reference-data owns language; merchant-store owns the store).

## Entity overview

| Entity | Table | Purpose | Lifecycle? |
|--------|-------|---------|------------|
| Admin user | `admin_user` | Back-office user identity, store scope, login timestamps | yes (active flag) |
| Group | `sm_group` | Named role container, typed ADMIN/CUSTOMER | no (reference-ish) |
| Permission | `permission` | Named authority (= role string in guards) | no |
| User↔Group | `user_group` | Membership join (M:N) | membership only |
| Permission↔Group | `permission_group` | Grant join (M:N) | membership only |

## Core Entities (executable PostgreSQL DDL)

```sql
CREATE SCHEMA IF NOT EXISTS identity_admin;
SET search_path TO identity_admin;

-- ============================================================
-- admin_user — back-office administrator identity
-- Maps to legacy USER. Credentials removed (ADR-004): idp_subject replaces ADMIN_PASSWORD.
-- ============================================================
CREATE TABLE admin_user (
    id              BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, -- Maps to USER.USER_ID
    user_name       VARCHAR(100) NOT NULL,                 -- Maps to USER.ADMIN_NAME (login name)
    idp_subject     VARCHAR(255),                          -- Required by ADR-004: OIDC subject (replaces ADMIN_PASSWORD)
    email           VARCHAR(255) NOT NULL,                 -- Maps to USER.ADMIN_EMAIL
    first_name      VARCHAR(100),                          -- Maps to USER.ADMIN_FIRST_NAME
    last_name       VARCHAR(100),                          -- Maps to USER.ADMIN_LAST_NAME
    merchant_id     BIGINT       NOT NULL,                 -- Maps to USER.MERCHANT_ID (TENANT xref, no FK — BR-SC-AUTHZ-001)
    language_code   VARCHAR(10),                           -- Maps to USER.LANGUAGE_ID resolved to ISO code (xref, no FK)
    active          BOOLEAN      NOT NULL DEFAULT TRUE,     -- Maps to USER.ACTIVE (BR-SC-AUTHN-001: inactive cannot log in)
    last_access     TIMESTAMPTZ,                           -- Maps to USER.LAST_ACCESS (BR-SC-AUTHN-004: prior login)
    login_time      TIMESTAMPTZ,                           -- Maps to USER.LOGIN_ACCESS (BR-SC-AUTHN-004: current login)
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- Audit/multi-tenancy standard
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- Audit/multi-tenancy standard
    created_by      VARCHAR(100),                          -- Audit/multi-tenancy standard
    CONSTRAINT uq_admin_user_name UNIQUE (user_name)       -- Required by BR-SC-UNIQ-001 (global uniqueness; per-tenant flagged for 4a)
);
CREATE INDEX ix_admin_user_merchant ON admin_user (merchant_id); -- BR-SC-LSTUSR-001 (list by store)
CREATE INDEX ix_admin_user_active   ON admin_user (active);      -- BR-SC-AUTHN-001

-- ============================================================
-- sm_group — named role container
-- Maps to legacy SM_GROUP.
-- ============================================================
CREATE TABLE sm_group (
    id              BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, -- Maps to SM_GROUP.GROUP_ID
    group_name      VARCHAR(100) NOT NULL,                 -- Maps to SM_GROUP.GROUP_NAME
    group_type      VARCHAR(20)  NOT NULL,                 -- Maps to SM_GROUP.GROUP_TYPE (BR-SC-RBAC-004: ADMIN|CUSTOMER)
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- Audit standard
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- Audit standard
    CONSTRAINT uq_group_name  UNIQUE (group_name),         -- Required by BR-SC-RBAC-003 (group name unique)
    CONSTRAINT ck_group_type  CHECK (group_type IN ('ADMIN','CUSTOMER')) -- Required by BR-SC-RBAC-004 (INV-SC-002)
);

-- ============================================================
-- permission — named authority (= role string checked by guards, BR-SC-RBAC-002)
-- Maps to legacy PERMISSION.
-- ============================================================
CREATE TABLE permission (
    id              BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, -- Maps to PERMISSION.PERMISSION_ID
    permission_name VARCHAR(100) NOT NULL,                 -- Maps to PERMISSION.PERMISSION_NAME (the authority string)
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- Audit standard
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- Audit standard
    CONSTRAINT uq_permission_name UNIQUE (permission_name) -- Required by BR-SC-RBAC-003 (permission name unique)
);

-- ============================================================
-- user_group — administrator ↔ group membership (M:N)
-- Maps to legacy USER_GROUP. Rows are insert/delete only (BR-SC-RBAC-001).
-- ============================================================
CREATE TABLE user_group (
    user_id         BIGINT NOT NULL,                       -- Maps to USER_GROUP.USER_ID
    group_id        BIGINT NOT NULL,                       -- Maps to USER_GROUP.GROUP_ID
    CONSTRAINT pk_user_group PRIMARY KEY (user_id, group_id),
    CONSTRAINT fk_ug_user  FOREIGN KEY (user_id)  REFERENCES admin_user (id) ON DELETE CASCADE, -- BR-SC-DELUSR-002 (delete cascades memberships)
    CONSTRAINT fk_ug_group FOREIGN KEY (group_id) REFERENCES sm_group  (id) ON DELETE CASCADE
);
CREATE INDEX ix_ug_group ON user_group (group_id);

-- ============================================================
-- permission_group — permission ↔ group grant (M:N)
-- Maps to legacy PERMISSION_GROUP. Rows are insert/delete only (BR-SC-RBAC-001).
-- ============================================================
CREATE TABLE permission_group (
    permission_id   BIGINT NOT NULL,                       -- Maps to PERMISSION_GROUP.PERMISSION_ID
    group_id        BIGINT NOT NULL,                       -- Maps to PERMISSION_GROUP.GROUP_ID
    CONSTRAINT pk_permission_group PRIMARY KEY (permission_id, group_id),
    CONSTRAINT fk_pg_perm  FOREIGN KEY (permission_id) REFERENCES permission (id) ON DELETE CASCADE, -- BR-SC-PERM-004 (delete nulls links first)
    CONSTRAINT fk_pg_group FOREIGN KEY (group_id)      REFERENCES sm_group   (id) ON DELETE CASCADE
);
CREATE INDEX ix_pg_group ON permission_group (group_id);
```

### DDL provenance notes

- `admin_user.idp_subject` — Required by ADR-004 (OIDC delegation); replaces the legacy `ADMIN_PASSWORD`.
- Legacy `ADMIN_PASSWORD`, `ADMIN_Q1..Q3`, `ADMIN_A1..A3` are **intentionally omitted** — credentials and
  the security-question reset flow move to the OIDC provider. The rules that used them (BR-SC-PWD-*,
  BR-SC-RESET-*) are preserved in `01-business-rules.md` for traceability only.
- `merchant_id`, `language_code` — external references (xref); no FK across service boundaries (ERD rule).
- Both join tables are keyed on their pair and hold no extra columns (legacy join columns are `updatable=false`).

## Entity State Model (Layer A)

Only `admin_user` has a lifecycle. `sm_group`, `permission`, and the two join tables are reference/membership
data with no status column.

#### admin_user lifecycle
- **States:** Active (initial), Inactive
- **Transitions:**

| From | To | Trigger (BR-ID) | Guard (precondition) |
|------|----|-----------------|----------------------|
| (none) | Active | BR-SC-CREATE-005 | user created (active defaults TRUE) |
| Active | Inactive | BR-SC-EDIT-002 | admin edits the account and clears the active flag |
| Inactive | Active | BR-SC-EDIT-002 | admin edits the account and sets the active flag |

- Active is the initial state (create defaults `active = TRUE`). There is no terminal state via the
  lifecycle: an account leaves the system by deletion (BR-SC-DELUSR-002), not by a status transition.
- Both non-terminal states have an outgoing transition (Active↔Inactive), so no dead-end state exists.
- `active` gates authentication: an Inactive account cannot log in (BR-SC-AUTHN-001).

## Data Invariants (Layer A)

| Invariant ID | Statement (domain terms) | Entity | Kind | Tier |
|--------------|--------------------------|--------|------|------|
| INV-SC-001 | An administrator login name is unique | admin_user | constraint | db |
| INV-SC-002 | A group's type is exactly one of administrator or customer | sm_group | constraint | db |
| INV-SC-003 | A group name is unique | sm_group | constraint | db |
| INV-SC-004 | A permission name is unique | permission | constraint | db |
| INV-SC-005 | An administrator holds a permission only through a group that grants it (no direct grant) | admin_user | cross-entity | app |
| INV-SC-006 | An inactive administrator cannot authenticate | admin_user | constraint | app |
| INV-SC-007 | A membership/grant link references an existing user/group/permission (no orphan links) | user_group, permission_group | referential | db |

- Integrity invariants (INV-SC-001/002/003/004/007) are DB-tier (UNIQUE / CHECK / FK) — data integrity
  cannot depend on the app being the sole writer.
- INV-SC-005 (two-hop RBAC) and INV-SC-006 (inactive-no-login) are business invariants enforced in the
  domain/authorization layer (app tier) — there is no single-table constraint that expresses them.

> No `### Database Logic Objects` section: MS-02 has no set-based/batch/DB-proc logic (P1 Layer C is empty).
> All integrity invariants are expressed as table constraints already present in the DDL above; no triggers,
> views, functions, or procedures are placed in the DB tier.
